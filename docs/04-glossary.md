# Glossary of Terms: AgentOps

## 1. Core Architectural & Domain Concepts

### Agent Operations (AgentOps)
The discipline and platform practice of deploying, monitoring, controlling, auditing, and securing autonomous and semi-autonomous AI workflows in production environments, ensuring deterministic reliability and resource bounds.

### Single Coordinator Architecture
An orchestration pattern where a single centralized state machine (implemented via LangGraph) directs the workflow, schedules tasks, and enforces validation rules. This contrasts with dynamic multi-agent swarms where agents message each other unpredictably.

### Execution Plan (DAG)
A validated, directed sequence of discrete steps generated by the coordinator to accomplish a user's research objective. The plan specifies dependencies, tool names, inputs, and safety checkpoints before any step is executed.

### Plan Step (`PlanStep`)
A single, bounded atomic unit of work within an execution plan. Each step defines an identifier, objective, allowlisted tool to invoke, parameters, retry limits, and whether human approval is mandatory prior to execution.

---

## 2. Safety & Security Terms

### Tool Allowlisting
A strict security policy where only explicitly registered, parameter-validated Python functions can be executed by the agent. Arbitrary command execution, dynamic shell evaluation, or raw database query execution is strictly prohibited.

### SSRF (Server-Side Request Forgery) Guard
A defense mechanism implemented in the network retrieval layer that validates target hostnames and resolved IP addresses against a blacklist of private (RFC 1918), loopback (`127.0.0.0/8`), link-local, and cloud provider metadata addresses (`169.254.169.254`).

### Human-in-the-Loop (HITL) Gate
A synchronization barrier where the execution state machine pauses automatically when encountering a consequential action, persisting its exact state until an authorized operator issues an explicit approval or rejection verdict.

### Approval Token
A cryptographically secure, time-bounded URL-safe string generated when an approval gate is reached. The token is required to authorize the resumption of the paused run.

---

## 3. Evidence & Analytical Terms

### Evidence Record (`EvidenceRecord`)
An immutable database entity storing factual source material retrieved by tools. It contains the source URI, exact excerpt, retrieval timestamp, and an SHA-256 content hash to verify authenticity.

### Citation Grounding
The verifiable linking of factual claims in the synthesized report to specific, immutable `EvidenceRecord` identifiers, enabling human operators to click directly from an assertion to its empirical source.

### Evidence vs. Inference
The deliberate structural separation within the generated report between:
1. **Factual Evidence**: Empirical data directly extracted from verified external sources (e.g., published pricing numbers, product feature lists).
2. **Analytical Inference**: Deductions, strategic synthesis, and market interpretations formulated by the AI model based on the evidence.

---

## 4. Operational & Infrastructure Terms

### Deterministic Mock Mode
An offline execution mode that utilizes deterministic, seeded mock LLM and search adapters with zero external network calls. It enables 100% reproducible testing, CI/CD execution, and portfolio evaluation without requiring paid third-party API credentials.

### Provider Adapter Pattern
An architectural interface abstraction (`BaseLLMAdapter`, `BaseSearchAdapter`) that decouples application business logic from external API providers (e.g., OpenAI, Ollama, Tavily), enabling drop-in substitution without code modifications.

### Durable State Checkpointing
The transactional persistence of the entire LangGraph workflow state to PostgreSQL after every node execution. This guarantees that worker restarts, network failures, or human approval delays do not result in state loss.

### n8n Community Integration
A self-hosted workflow automation engine deployed alongside AgentOps to handle edge integrations—such as listening for scheduled cron triggers, dispatching Slack/email notifications, or handling external webhook ingestion—leaving core domain logic inside Python.
